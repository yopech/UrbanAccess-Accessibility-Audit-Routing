# Требования к пилоту с НКО

Эта версия заменяет прежние требования к графу как объём текущей реализации. Ранние FR-001…FR-084 сохранены в [архиве](archive/03-requirements.md).

| ID | Требование | Проверяемый результат |
|---|---|---|
| P-01 | Создать и выбрать проект с частями пути | Без названия, начала/конца, требований, цели, координатора и частей задание не сохраняется |
| P-02 | Привязать полевую запись к проекту и части | Готовая запись требует участника, основания оценки, времени, координат, ориентира и фото |
| P-03 | Оценивать проход раньше физической причины | PRESENT требует ограничения и альтернативы; тип препятствия необязателен; указанный обход описан словами |
| P-04 | Различать свободную точку и исчезновение прежней проблемы | CLEAR_PASSAGE не подтверждает весь путь; ABSENT требует ссылки на прежнюю запись |
| P-05 | Сохранить черновик | Фото и точные координаты необязательны; проект и корректное время обязательны |
| P-06 | Решение принимает координатор | Имя и основание обязательны, решение добавляется в историю; ASSUMPTION нельзя принять |
| P-07 | Разбирать противоречия вручную | Близость до 15 м внутри одной части/контекста и совместимого уровня лишь подсказывает пару; разбор требует объяснения |
| P-08 | Отдельно подтверждать охват | Для CHECKED нужны дата, проверяющий, основание обследования и принятое наблюдение; координатор подтверждает полноту перечня частей |
| P-09 | Ограничить положительные выводы | Нельзя сохранить PASSABLE/CONDITIONAL при непроверенных частях, открытых противоречиях, ожидающих решениях, спорном задании или истёкшем сроке |
| P-10 | Вывод соответствует данным | PASSABLE запрещён при принятых ограничениях; BLOCKED требует принятого BLOCKED; самостоятельный обход заблокированного места не может быть NONE/UNKNOWN/ASSISTED |
| P-11 | Сохранять историю при новом осмотре | Готовая запись исправляется новой версией; recheck начинает новое наблюдение без старых фото; замена требует приёмки и сопоставимой даты |
| P-12 | Не удалять проблему по давности | Срок назначает координатор; после срока положительный итог становится UNKNOWN, прежние сведения сохраняются |
| P-13 | Пересматривать вывод после изменений | Изменение данных, охвата, задания или разбора пары делает прежний вывод неактуальным до нового решения |
| P-14 | Обмениваться файлами без перезаписи | Задание без наблюдений; результаты одного проекта; полная копия; предпросмотр; идентичный импорт пропускается, отличающаяся запись получает отдельную версию |
| P-15 | Импортировать атомарно и сохранять старое | До записи проверяется весь файл; повреждённый файл ничего не меняет; версия 1 и миграция IndexedDB сохраняют фотографии и записи |
| P-16 | Получить честный отчёт | Проект, метод, требования, даты, охват, неизвестные части, решения/разборы, версии, фото и вывод доступны в HTML и печати |
| P-17 | Отделить учебные данные | Демо явно помечено, использует вымышленные схемы; реальные записи не привязываются к нему |
| P-18 | Работать на телефоне и без сети | На ширине 320 px нет горизонтального переполнения; после загрузки оболочки работают сбор, пересмотр и отчёт; отсутствие тайлов не блокирует форму |

## Семантика решений

Результат участника и проверка независимы: `status=DRAFT/READY`, `reviewStatus=UNREVIEWED/ACCEPTED/NEEDS_CLARIFICATION/REJECTED`. Статус проекта не равен выводу о доступности. Завершённая проверка может закончиться выводом «данных недостаточно».

`BLOCKED` описывает невозможность самостоятельного прохода, `DIFFICULT` — самостоятельный проход с усилием, `RESTRICTED` — зависимость от требований/возможностей. Помощь другого человека не считается самостоятельным проходом.

Если две записи совместимы, координатор объясняет различие условий. После изменения любой из них такой разбор перестаёт закрывать подсказку. Если состояние изменилось, принимается новая запись и явно заменяется старая. Если запись неверна, она отклоняется с основанием. Автоматическая дедупликация или снятие ограничения по близости запрещены.

## Проверки

Исполняемые правила проверяются в `frontend/tests/pilot.test.mjs`. Проверки браузера — `frontend/tests/browser.mjs`: миграция, обмен, повторный и конфликтный импорт, полевой сбор, приёмка, отчёт, офлайн и мобильные размеры. Прежние проверки GPS и формы сохранены в `frontend/tests.html`.

Локальный прототип не удостоверяет личности и не защищает историю от намеренного изменения JSON. Это ограничение архитектуры, а не скрытая гарантия достоверности.
