# Предметная модель текущего пилота

## Объекты

| Объект | Содержание | Хранение |
|---|---|---|
| Audit Project | Название, партнёр, координатор, начало/конец, требования, цель, инструкция, этап, даты, признак демо | IndexedDB: projects |
| Route Part | ID, название, охват, кто/когда обследовал, основание | Массив parts внутри проекта |
| Observation | Проект и часть, факты, фото, участник, источник оценки, готовность и решение | IndexedDB: observations |
| Photo | Blob, имя, MIME, размер, observationId | IndexedDB: photos |
| Review Decision | Статус, комментарий, имя проверяющего, время | reviewHistory внутри Observation |
| Pair Resolution | Два ID, версии записей, основание совместимости, координатор, время | pairResolutions внутри проекта |
| Route Conclusion | Вывод, основание, дата, срок recheck и отпечаток исходных сведений | Поля проекта и conclusionHistory |

Один проект содержит одну последовательность частей. Участник выбирает часть для записи. У старых наблюдений связь с проектом и частью может отсутствовать до ручной привязки. Порядок частей задаёт координатор; геометрия маршрута не рассчитывается.

## История и повторный осмотр

Черновик редактируется на месте. Изменение READY создаёт новый ID с previousObservationId. Старое наблюдение сохраняется. Recheck копирует место, но требует новых фото и текущего времени.

После приёмки новой записи координатор может явно назначить старой supersededById. Обе остаются в базе и отчёте; в текущих итогах учитывается только незаменённая версия. Между разными проектами или частями такая замена запрещена. Более раннее наблюдение не заменяет более позднее.

## Итог и свежесть

Проект хранит UNKNOWN / PASSABLE / CONDITIONAL / BLOCKED. Пользовательский итог вычисляется с учётом охвата, ожидающих решений, споров и срока повторной проверки. Изменение оснований требует пересмотра вывода.

Повторный осмотр не запускается автоматически. Координатор назначает срок с учётом изменчивости условий: ремонт и лифт могут требовать иной частоты, чем бордюр. Трёхмесячное молчание не снимает ограничение.

## Файловый обмен

Формат urban-accessibility-field-backup версии 2: проекты и наблюдения с фотографиями base64. Варианты: ASSIGNMENT, RESULTS, BACKUP. Старый формат версии 1 принимается без проекта.

Повторный файл распознаётся по содержимому. Другой вариант существующего ID сохраняется под отдельным детерминированным ID, связанным через conflictOfId; требует решения. Описание проекта координатора не перезаписывается входящим заданием: другая версия сохраняется для сравнения. Локальные отметки охвата и выводы имеющегося проекта не заменяются файлом участника.

## Отложенная модель графа

Прежняя модель [Observation → Barrier → Accessibility Impact](archive/05-domain-model.md) сохранена как исследовательский задел. Её автоматические LINK_ONLY / CONFIRM / CONFIRM_AND_EXTEND и влияние на маршрутизатор здесь не выполняются. При возвращении к графу семантические противоречия остаются за модератором, а давность не должна автоматически отключать влияние.
