# Шаг 1.4: фотографии обследования

## Обработка

`src/media/audit-media.ts` проверяет размер и сигнатуру файла перед декодированием. Лимит входа 20 МиБ. JPEG, PNG и WebP декодируются штатным API браузера. SVG, исполняемые файлы и неподдерживаемое содержимое отклоняются, включая файлы с ложным MIME. HEIC/HEIF принимается только при успешном нативном декодировании; иначе предлагается выбрать JPEG.

Штатный декодер применяет EXIF-ориентацию. Приложение не поворачивает результат повторно. Основной путь использует ImageBitmap с `imageOrientation: from-image`; резервный путь использует HTMLImageElement. В конце освобождаются ImageBitmap, временный URL и размеры canvas.

Обычная копия ограничивается 2560 пикселями по длинной стороне без увеличения. Выходной формат JPEG; прозрачность исходного PNG/WebP накладывается на белый фон. Сжатие подбирается от качества 0,94 до 0,82 с целью 3 МиБ. Качество не понижается безгранично: если цель не достигнута, интерфейс явно сообщает размер. Перед добавлением обязательный предварительный просмотр позволяет увеличить шкалы и выбрать подробную копию исходного разрешения. Подробная и уменьшенная копии являются альтернативами; автоматически сохраняется только выбранная. Выходной файл ограничен 20 МиБ. Исходный EXIF/GPS не копируется в новый JPEG.

Читаемость шкал подтверждает пользователь на превью. Алгоритм не обещает автоматически распознать, читаются ли деления прибора. SHA-256 вычисляется через crypto.subtle по итоговому Blob, после обработки.

## Атомарное хранение

Photo содержит UUID, auditId, elementId, measurementIds, findingIds, Blob, MIME, SHA-256, bytes, width, height, caption и createdAt. В Audit и Element находятся только photoIds; замеры и замечания связаны идентификаторами. Blob не помещается в Audit, JSON-строки или BroadcastChannel.

AuditStore расширен синхронным обработчиком дополнительных хранилищ. Для рабочего сервиса одна транзакция охватывает audits, auditEvents и auditPhotos. В ней проверяется expectedRevision, применяются команды, добавляется снимок и фиксируются связи. Ни декодирование, ни хеширование внутри транзакции не выполняются. События содержат метаданные фотографии без дублирования Blob. Уведомление отправляется после oncomplete.

Добавление фото использует add(), поэтому существующее бинарное содержимое не перезаписывается. Подпись и связи изменяют только метаданные при сохранении исходного Blob, UUID и хеша. Связи допустимы только с замерами и замечаниями того же элемента; историческая версия замера остаётся доступной как основание фотографии.

Обследования прежнего шага M1, где у элементов ещё отсутствует photoIds, получают пустые массивы в нормализованной копии при чтении. Исходные маршрутные хранилища observations, photos и projects остаются неизменными. Версия базы остаётся 3: auditPhotos уже создано в Фазе 0.

## Квота и отвязка

QuotaExceededError откатывает всю транзакцию. Редактор показывает ошибку, сохраняет очередь команд и не сообщает «Сохранено». Пользователь может повторить запись после освобождения места или убрать только несохранённое фото, сохранив текстовые команды. Пока ошибка не разрешена, переход на другой экран и обновление приложения не подтверждаются как безопасные.

Отвязка требует отдельного подтверждения и атомарно удаляет рабочие ссылки из Audit, Element и Finding. Снимок физически не удаляется: он остаётся доступным для истории и будущих снимков документов. В текущей карточке есть действие «Вернуть фото». Сборщик неиспользуемых Blob в этом шаге не реализован, поэтому отвязка сама по себе не освобождает дисковую квоту.

## Интерфейс и проверки

Кнопка камеры имеет 56 × 56 px и видимую подпись. Есть отдельный выбор съёмки и файла. Превью и галерея используют object URL с отзывом при замене/размонтировании. Просмотр реализован через Radix Dialog: название, описание, удержание фокуса, Escape, возврат фокуса, увеличение до 400%, показ в исходном размере и прокрутка внутри изображения. Горизонтальная прокрутка страницы не требуется.

- AC-02: две двери сохраняют собственные фотографии и связи после перезагрузки.
- AC-14: контролируемая имитация QuotaExceededError в нативной IndexedDB проверяет откат ревизии, ссылок и Blob, сохранение текста, предупреждение в UI и повторное сохранение без неудавшегося фото.
- NFR-01: проверены размеры кнопки, подписи, увеличение, удержание/возврат фокуса и ширина 320 px.
- Дополнительно: JPEG/PNG/WebP, два пути EXIF-ориентации, HEIC с ошибкой, SHA-256, ресайз, отзыв URL, отвязка и возврат.

Запуск проверок: `pnpm typecheck`, `pnpm test:editor`, `pnpm test:media`, `pnpm test:storage`, `pnpm test:m1`, `pnpm test:phase0`. Браузерные сценарии требуют Chromium/Playwright. Тестовый media-harness включается только специальной тестовой сборкой и отсутствует в обычном dist.
