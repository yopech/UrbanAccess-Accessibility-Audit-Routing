# UrbanAccess: обследования доступности

UrbanAccess помогает фиксировать результаты обследования объектов. В текущей локальной сборке доступен редактор входной группы Z2 с фото, опциональной диктовкой, сводкой и экспортом DOCX: реквизиты объекта, отдельные карточки элементов, замеры, замечания и автоматическое сохранение.

Основной развиваемый сценарий проекта: обследование доступности здания и подготовка черновика акта для экспертной проверки. Прежний маршрутный режим поддерживает задания, полевые записи, диктовку комментария, обмен файлами и печатный отчёт. Объектный режим поддерживает фотографии с подписями и связями с замерами, диктовку, экспертную проверку и автономное формирование черновика фрагмента акта Z2. Сохранённые редакции документов остаются неизменными после правок обследования. Развитие предусматривает гранты и спонсоров, затем платное внедрение и сопровождение.
[Открыть приложение](https://yopech.github.io/UrbanAccess-Accessibility-Audit-Routing/frontend/) · [Открыть учебное демо](https://yopech.github.io/UrbanAccess-Accessibility-Audit-Routing/frontend/?demo=1)

## Что попробовать в прежнем маршрутном режиме за пять минут

1. Открыть демо: вымышленный путь от остановки до общественного центра.
2. Перейти в «Результаты»: увидеть принятые наблюдения, противоречие и непроверенный вход.
3. Нажать «Заполнить учебную запись», сохранить её готовой к проверке.
4. В карточке открыть «Решение координатора» и записать решение с основанием.
5. Открыть отчёт. Скачать HTML с фотографиями или выбрать «Печать / PDF».

Демонстрационные точки, иллюстрации и решения вымышлены. Они не описывают реальную территорию и не подтверждают наличие партнёра.

## Как работает настоящий пилот

Координатор создаёт маршрут с конкретными началом, входом, требованиями к проходу и перечнем частей. Он скачивает файл задания и передаёт участникам. Участники импортируют задание, сохраняют наблюдения с фото и возвращают файлы результатов. Координатор объединяет их, разбирает спорные места и формирует отчёт.

Данные остаются в браузере устройства. Общего сервера, аккаунтов, автоматической синхронизации и отправки НКО нет. Имена и решения в импортированном файле не удостоверяются приложением. Сохраняйте полную копию перед сменой устройства или очисткой браузера.

Прежние записи и фотографии сохраняются при обновлении. Записи без проекта можно вручную привязать к реальному маршруту. Поддерживается импорт старой копии версии 1.

## Границы

- Карта показывает точки, а не рассчитывает путь. Геолокацию нужно проверить вручную.
- Отсутствие меток не означает доступность. Обследование каждой части подтверждает координатор.
- Предположение не принимается как проверенное наблюдение.
- Давность не доказывает исчезновение препятствия. Повторная проверка сохраняет прежнюю запись и историю решений.
- Отчёт — материал ограниченного обследования; он не заменяет официальный акт и не гарантирует проход.

## Запуск и проверки

Приложение собирается Vite и работает полностью на устройстве, без API-ключа и серверной базы. После установки Node.js и pnpm:

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm typecheck
pnpm test
pnpm test:editor
pnpm build
```

Для обычной локальной сборки с коротким путём используйте `URBANACCESS_BASE=/frontend/ pnpm build`. По умолчанию настроен путь GitHub Pages `/UrbanAccess-Accessibility-Audit-Routing/frontend/`. Результат сборки находится в `dist`; корневой `dist/index.html` переводит в `frontend/`. Для публикации требуется раздавать содержимое **dist**, а не исходные TypeScript-файлы. В этой задаче публикация и настройка GitHub не выполняются.

PWA устанавливает один Service Worker. Новая версия применяется кнопкой после успешного сохранения во всех открытых вкладках. Незавершённая форма старого режима или неотвечающая вкладка откладывает обновление. Для первоначального перехода со старой поставки с собственным SW может потребоваться закрыть прежние вкладки и открыть приложение заново.

Живое тестирование на Android по USB: [инструкция подключения](docs/15-live-phone-testing.md).

Дополнительные проверки: `pnpm test:storage`, `pnpm test:phase0`, `pnpm test:m1`, `pnpm test:media`, `pnpm test:voice` и `pnpm test:review`. Они требуют Playwright с установленным Chromium; тесты сами запускают локальный сервер. Путь к внешней установке Playwright задаётся через `PLAYWRIGHT_MODULE_PATH`.

Старый маршрутный интерфейс находится в `legacy.html` и монтируется в изолированном документе. Он открывает общую IndexedDB версии 3, сохраняя прежние наблюдения и фото. В объектном режиме доступны Z1 (территория), Z2 (вход), Z3 (пути внутри здания) и Z4 (санузел). Новые зоны создаются при первом выборе в редакторе.

## Диктовка комментария в прежнем маршрутном режиме

В разделе комментария есть кнопка «Продиктовать комментарий». Разрешите микрофон, произнесите короткую фразу и завершите диктовку. Проверьте распознанный текст перед сохранением. Измерения заполняются отдельно. Сброс формы и переход на другой экран останавливают диктовку. Сервис браузера может обрабатывать речь через сеть; приложение сохраняет только текст.

Поддержка зависит от браузера. Если диктовка недоступна, можно написать комментарий или использовать микрофон экранной клавиатуры. Отчёт прототипа остаётся отчётом наблюдений, а не автоматически подготовленным актом обследования здания.

Проверка сценария: `node frontend/tests/dictation-browser.mjs`. Автоматический тест моделирует распознавание без доступа к микрофону; точность реальной речи проверяется на устройстве.

## Ручное обследование входной группы Z2

В новой сборке стартовый экран содержит обследования объектов. Создайте объект, явно выберите Z2, заполните карточки элементов и подтвердите завершённые записи. Вторую дверь или поручень можно добавить отдельным экземпляром. Записи автоматически сохраняются на устройстве и открываются без сети после первого запуска. Архив хранит обследование в режиме чтения.

Описание объёма и проверок: [M1: модель Z2 и редактор](docs/12-m1-z2-editor.md). Для нового режима выполните `pnpm test:m1`. Фото уже доступны: [обработка, хранение и галерея](docs/13-audit-media.md), проверка `pnpm test:media`. Диктовка комментария и рекомендации уже подключена: [сеансы, черновики и проверка текста](docs/14-m1-dictation.md), `pnpm test:voice`. DOCX и печать доступны автономно. Доступ к прежнему режиму маршрутов временно закрыт; сохранённые маршрутные данные остаются в локальной базе.

Сводка и автономные документы: [описание реализации и проверок](docs/16-m1-review-and-documents.md).

Обследование нескольких зон: [Этап 2.3: модель, профили и совместимость](docs/20-m2-object-zones.md). Проверка полного цикла: `pnpm test:zones`.

Сводный документ объекта и дефектная ведомость: [Этап 2.4](docs/21-object-act-and-defects.md).
